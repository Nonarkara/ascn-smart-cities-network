# ASCN design, usability and publication audit

Owner scope: apply the supplied anti-slop rules, learn from Axiom X, stabilise
interactions, and publish only public material. The shared workspace already
adopts anti-slop-design; this project now carries AGENTS.md, the seven-rule
section, an objective release gate, and a repeatable screenshot command.

## Publication and security

The previous release exposed redacted mailbox snippets and build-only archive
modules. Both paths are closed. Private source material remains locally in
ignored storage; it is not a public dataset. Unadopted meeting drafts and
unverified draft assets are also excluded. The public archive retains 40
public-source records and recalculates funding from those rows.

The release uses explicit dataset, runtime-module and asset lists. The archive
projection constructs approved fields only, excludes private provenance and
withheld-record metadata, and omits unsourced personal statements. Unknown
translation fields fail validation. A canonical SHA-256 fingerprint rejects
new or changed archive content until its source review is recorded. A URL and
redaction alone cannot clear private-derived prose.

Private paths return non-cacheable 404 responses. Contact-directory PDFs with
unclear republication provenance are replaced by the official ASEAN page;
the planning guide points to the published JASCA edition. Existing public
maps, source links, project analytics, videos and research remain available.

Dependencies: npm audit reports zero vulnerabilities. Gitleaks scanned 105
historical commits and flagged 12 generic-key matches; all are synthetic SHA
thread identifiers, not credentials. This does not clear the privacy of those
historical records. The scan output and snapshot inventory stay local.

## Verification and limits

`npm run check`: design gate, public-data validation, 57 unit tests passed; one
source-rebuild test explicitly skipped because its external source folder is
not configured. Full browser suite: 44 passed. Targeted checks also cover the
final map and navigation changes. Browser tests exercise hostile text/links,
XML bounds, source-only publication, private-route denial, CSV export, maps,
video playback, keyboard search, and responsive layouts.

The owner approved deletion of the 19 exposed historical deployment snapshots.
All 19 deletions succeeded; the fresh Cloudflare deployment inventory contains
exactly the other six deployments, including the protected current release.
Public URL verification remains a separate check: four deleted hosts return
404 for both the root and correspondence path, while 15 still return HTTP 200.
Their removal from the deployment list does not establish that cached responses
are gone. The custom domain and current immutable release match the safe build;
both deny the private JSON path with a non-cacheable 404.

Old Git commits remain public. A local review plan inventories affected refs,
private paths and mixed public/private files, with a proposed isolated rewrite
and preservation checks. No history rewrite or force-push has been performed.
Deletion receipts, per-host checks and the review plan stay in ignored local
storage. Previously downloaded copies and third-party caches remain outside
this cleanup’s guarantees.

## Follow-up publication guard

Every finished static build now verifies its actual file tree against the
publication policy, rejects hidden files and symlinks, requires root assets
including security headers, and checks the archive fingerprint again. Six
regression tests inject forbidden files, tamper with the archive, remove headers,
and simulate stale assets, leaked private routes, redirects and network errors.
The standard deployment command verifies live file bytes and GETs 13 private
routes, requiring no-store 404 responses. This does not resolve old Git objects
or the remaining historical snapshot responses described above.
